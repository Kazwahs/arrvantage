Metadata Services
Movie/TV Metadata (TMDB)
Powers the "click a cast member's name" feature in movie/show detail views. Optional - skip this if you don't want that feature. Get a free API key from themoviedb.org under Settings → API.
TV Cast Data (TVDB)
Powers the cast list on Sonarr shows specifically - Sonarr's own API doesn't expose this. Optional, and note TVDB's API requires an active $12/year TheTVDB subscription tied to your key. Get a key at thetvdb.com under Dashboard → API Keys.
Music Images (Fanart.tv)
Better artist images for Lidarr than what Lidarr's own data reliably provides - applies to both the library grid and artist detail views. Optional. Get a free API key at fanart.tv under your account settings.
Artist Bios (TheAudioDB)
Lidarr/MusicBrainz has no artist biography data at all, so this fills that gap. Works out of the box with the shared public test key (already filled in below) - only change this if you have your own TheAudioDB key.
Activity Data (Tautulli)
Improves the Plex tab's Now Playing, Watch History, and Users views by pulling from Tautulli's own tracked data instead of Plex's own limited endpoints - most notably, this can see shared/"friend" users that Plex's local API can't. Optional; only affects Plex, not Jellyfin/Emby. Get the API key from Tautulli's own Settings → Web Interface.
Activity Data (Tracearr)
A multi-platform alternative to Tautulli/native APIs, covering Plex, Jellyfin, and Emby from one place. If configured, this takes priority over Tautulli for Now Playing, Watch History, and Users, and covers Recently Added too. Matches activity to each media server by comparing its name here to the server name in Tracearr, so keep those names consistent. Generate the API key in Tracearr under Settings → General.

Alerts

Push alerts for {{ session.get('username', 'your account') }}

Get a message on your phone when a service stops answering, and another when it is back. arrVantage checks in the background, so this works with the dashboard closed. Each administrator sets up their own alerts; they are not shared. A problem is only reported once it has been seen on two checks in a row, so one slow answer does not wake you up.

Background checks are switched off (MONITOR_INTERVAL=0), so no alerts will be sent.

ntfy

Install the ntfy app, subscribe to a topic of your choice, and enter the same topic here. Anyone who knows the topic can read your alerts on the public ntfy.sh server, so make it hard to guess, or use your own ntfy server.

Discord

Post alerts to a Discord channel. In Discord, open the channel's settings, then Integrations, Webhooks, create one, and choose Copy Webhook URL. The address works like a password, so anyone who has it can post to that channel; arrVantage stores it like an API key and never shows it again. Alerts never ping anyone.

Telegram

Send alerts to a Telegram chat through a bot of your own. In Telegram, message @BotFather, send /newbot, follow the questions, and copy the token it gives you. Then open your new bot and send it any message (to use a group instead, add the bot to the group and write something there). Paste the token below and press Find my chat. The token works like a password; arrVantage stores it like an API key and never shows it again.

Email

Send alerts by email through a mail server you can log in to (your provider's, or one on your own network). Gmail, Yahoo and most others need an app password rather than your normal one, created in the account's security settings. The login and password are stored like an API key and never shown again. Mail to your own phone's address is fine, but a slow or blocked mail server can delay an alert, so keep ntfy, Discord or Telegram as well for the important ones.

Slack

Post alerts to a Slack channel. In Slack, create an app for your workspace (api.slack.com/apps), switch on Incoming Webhooks, choose Add New Webhook to Workspace, pick the channel, and copy the address it gives you. The address works like a password, so anyone who has it can post to that channel; arrVantage stores it like an API key and never shows it again. Alerts never ping anyone.

Pushover

Send alerts to the Pushover app on your phone. On pushover.net, copy your user key from the home page, then create an application there (any name) and copy its API token. Both are stored like an API key and never shown again. A critical problem is sent as high priority, which can get through your phone's quiet hours.

Gotify

Send alerts to your own Gotify server. In Gotify, open the Apps tab, create an application, and copy its token. Enter the address you use to open Gotify (arrVantage has to be able to reach it from where it runs). The token is stored like an API key and never shown again.

Webhook

arrVantage sends a JSON message to this address (a POST with app, version, event, title, message, severity, kind, services, since and ended). Use it for Home Assistant, n8n and the like (Discord has its own box above, because it expects a different message). The address is stored like an API key, because many include a secret.

The test goes to what you last saved. Passwords, tokens and addresses are never shown here again once saved, and a blank box keeps what is saved.

Backup, restore and diagnostics

Export settings

Downloads your instances, services, accounts and metadata keys as one JSON file.

Left off, the file is safe to share but cannot restore your keys or accounts (importing it keeps the ones already set up). Turned on, the file is a full backup: keep it private.

Restore from a file

Choose a file exported from arrVantage. You will see what it changes before anything happens, and your current settings are saved as a backup file next to config.json first.

Diagnostics for a bug report

Copies a summary of your setup (types and counts only) and the most recent warnings. It never contains API keys, passwords, usernames or the names you gave your services.
